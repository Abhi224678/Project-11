# Project 11: Infrastructure Changes with Branching Policy

## Objective

To understand and implement Git branching strategies and manage infrastructure code changes using feature branches and Pull Requests.

## Tools Used

- Linux VM (Ubuntu)
- Git
- GitHub
- Terraform

## Implementation Steps

1. Created a separate project directory for Project 11.
2. Created a Terraform configuration file (`main.tf`).
3. Initialized a Git repository with the `main` branch.
4. Committed the initial Terraform configuration.
5. Created a feature branch named `feature/project11-update`.
6. Updated the Terraform configuration on the feature branch.
7. Committed and pushed the feature branch to GitHub.
8. Created a Pull Request to merge the feature branch into `main`.

## Branching Strategy

- **Main branch:** Contains the initial Terraform configuration.
- **Feature branch:** Contains the infrastructure configuration update.
- **Pull Request:** Used to review and merge the changes into the main branch.

## Deliverables

- Terraform configuration (`main.tf`)
- GitHub repository containing the project
- Feature branch: `feature/project11-update`
- Pull Request screenshot and link

## Result

Successfully implemented a Git branching workflow for infrastructure code and created a Pull Request for reviewing changes before merging them into the main branch.
